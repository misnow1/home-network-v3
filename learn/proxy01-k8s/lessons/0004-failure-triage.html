Lesson 0004 · Hybrid edge

Failure triage on the hybrid edge

One idea: isolate the hop before you change config. Timeout, 502, 404, and Accepted=False each point at a different layer.

Why this matters for your mission

You already proved the happy path for whoami.2123studios.com. At work, the skill that transfers is not “remember the YAML” — it is naming which hop failed from a symptom. Same stack: edge proxy → LB VIP → Gateway → Route → Service → Pod.

Knowledge — four symptoms, four layers

Map symptoms to the hop map (reference). Runbook table: kubernetes-runbook troubleshooting.

Symptom Broken hop (usual) ───────────────────── ────────────────────────────── timeout / no connect VLAN 1→9 firewall, or MetalLB ARP 502 from proxy01 Envoy up? VIP? backends Ready? 404 (with correct Host) HTTPRoute host/path mismatch Accepted=False Gateway allowlist / refs / ports 401/302 to Authelia edge auth (usually NOT the VIP)

1. Timeout — packets never arrive

From proxy01 (or VLAN 1): curl -sS -o /dev/null -w '%{http_code}\n' http://192.168.9.200/ hanging or “Connection timed out” means the VIP is not reachable — UniFi VLAN 1→9 allow for proxy→VIP, or MetalLB not answering ARP on VLAN 9. 

# On a VLAN 9 host / via kubectl debug node if needed:
ip neigh show 192.168.9.200
kubectl get svc -n envoy-gateway-system
# EXTERNAL-IP must be 192.168.9.200 (not <pending>)

2. 502 from proxy01 — TCP works, upstream unhappy

nginx reached something but got a bad gateway response. Check Gateway / HTTPRoute / Envoy Service, and that backends are Ready — not Authelia first (Authelia failures look like redirects/401, not classic 502 to the VIP). 

kubectl get gateway,httproute -A
kubectl get pods -n envoy-gateway-system
kubectl -n whoami get pods,svc,httproute

3. 404 — L7 routing miss

You already saw this on purpose: VIP up, wrong or missing Host. Same class of bug: nginx server_names ≠ HTTPRoute hostnames, or Host rewritten to the VIP IP.

4. Accepted=False — control plane said no

kubectl describe httproute … status reasons usually: Gateway allowedRoutes blocked the namespace, parentRef name/namespace wrong, Service/port name mismatch, or (later) missing ReferenceGrant for cross-namespace backends. (Gateway API model)

Order of checks: public HTTPS symptom → curl VIP from proxy01 with Host → kubectl get gateway,httproute,svc → describe route → pod Ready. Do not start in Authelia config for timeouts/502s to the VIP.

Skill — diagnose from the symptom (retrieval)

Mentally walk your live path. Prefer the first failing hop — do not stack unrelated fixes.

Check (retrieval)

Check (retrieval)

Check (retrieval)
